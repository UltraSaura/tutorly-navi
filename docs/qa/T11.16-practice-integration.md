# T11.16 — Practice integration

## Architecture and implementation

- Reused the existing authenticated Practice subject route (`/practice/:subject`) inside `MainLayout`; no separate product route, auth flow, quiz engine, score store, or schema was added.
- The Stuwy entry is eligible only for a CM1 Maths subtraction topic already present in Practice with an active assignment. Before mounting the session, the page checks Tutorly’s existing `useAllBanks(..., 'practice')` result for an unlocked bank at the current learner level.
- The student session is the same shared component used by the development Teacher Lab. It stores session state, attempts, hints, answer draft and selected tab in `sessionStorage`, keyed by learner and topic. It makes no Supabase writes.
- Completion links come from the selected topic’s existing lesson content, active videos, and unlocked Practice bank. Missing resources produce no link. Continuing to Practice opens the existing quiz route.
- Existing Practice quizzes and flashcards were not changed. No parent-portal, homework, database, RLS, migration, or production-data changes were made.

## Remaining risk / release gate

The conditional integration is implemented, but a signed-in CM1 learner with a matching active subtraction topic and unlocked Practice bank is required to visually verify the live launch and completion flow. The current QA environment cannot provide that context. Treat Practice integration as **implemented, live-data verification blocked**, not release-accepted.
