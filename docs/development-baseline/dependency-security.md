## Compatibility decisions

- Applied non-forced `npm audit fix`, keeping direct dependencies within their declared compatibility ranges.
- Pinned Capacitor core, Android, iOS and CLI to 7.6.10 to remove the Android advisory and keep the native packages aligned. CLI-selected transitive major changes are upstream-managed within Capacitor 7; no application API migration was imposed.
- Scoped the typography override to `postcss-selector-parser@6.1.6`. Typography pins 6.0.10, while the patched parser retains the same major/API. Clean install and CSS/web build verify compatibility at the build layer.
- MathLive asset copies changed only their version-banner comments (0.97.3 → 0.97.4); CSS rules are identical.
- No forced upgrades. Native compilation/device compatibility remains unverified because the environment lacks a full JDK/Android SDK.
- Deferred major/pre-1.0 minor migrations: Vitest/tinypool, Vite/esbuild, React Router, MathLive, KaTeX and Zod. These affect mocks/runner behavior, build plugins, navigation, mathematical input/rendering or schema APIs. Replacing them just to clear audit would exceed safe compatibility fixes.
- Glob/minimatch fixes require majors outside current parent ranges. TypeScript-ESLint, rimraf and sucrase inherit these findings; upgrading a parent within its current range is not sufficient. Do not override these majors blindly.

## Exposure and follow-up

Vitest runs in batch mode without a UI server in CI; it remains unpatched and is not represented as safe. Vite is a development/build dependency; do not expose its development server to untrusted networks. Runtime Zod, MathLive, KaTeX and Router findings need dedicated migration/regression work. Current audit status is not a clean security certification.

First prioritize the two critical Vitest/tinypool entries with a tested runner upgrade, then Vite and runtime validation/rendering/navigation upgrades. Each migration needs its own compatibility review. No production service, database or credentials were accessed for this review.
