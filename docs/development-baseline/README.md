## Lint policy and remaining debt

`npm run lint` remains the full strict ESLint command and still exits nonzero. No existing lint rules were disabled. New Node CI scripts also receive recommended JavaScript rules. Generated artifacts are ignored.

`npm run lint:ci` runs ESLint over the entire repository. Each accepted legacy diagnostic is identified by path, rule, severity, message and a SHA-256 hash of its trimmed source line. Line-number shifts/indentation do not create false failures. Changed source, new files, copied/duplicate violations, new warnings and parser errors fail the gate. This is a source-line baseline, not whole-file exemptions or a blanket count allowance.

The baseline was derived from the original commit under the current installed toolchain, then pruned to remove resolved entries. It is not automatically regenerated by CI. Treat additions or changes to `config/lint-baseline.json` as explicit reviewable debt exceptions; normal fixes should only remove entries. Identical existing source lines retain their allowance; this is not a full semantic code-diff analysis.

## CI architecture

- `verify-web.yml` is a reusable verification job: clean install, application/config types, lint gate and its Node tests, Vitest, web build, then always-uploaded evidence.
- `development-baseline.yml` runs on PRs except the existing Android target branches, plus manual dispatch. Concurrency cancels superseded runs.
- `private-beta-android.yml` keeps its existing triggers and native candidate-build steps, calls the same verification job, and waits for it. Duplicate root type checks/tests were removed from the native job. Its Node version now follows `.nvmrc`.
- Jobs have read-only repository permissions, no inherited deployment secrets, and timeouts. New action references are pinned to verified commit SHAs.
- Type/lint/test/build steps continue gathering evidence after earlier check failures when installation succeeded; failures still fail the job. Artifact upload uses `always()`, with 14-day retention.
- Artifacts contain install/type/lint/test/build logs, complete ESLint JSON, lint summary and JUnit XML. They do not include `.env`, credentials, source datasets or production data.
- Native APK/AAB output collection and the existing no-store-publication behavior remain unchanged. Branch protection/required-check settings were not changed.

- Native JDK/SDK/emulator blockers from the audit remain. Capacitor native package alignment is not device certification.
- Deno-specific execution remains outside this web baseline; the existing Vitest-compatible function tests do run. Mechanical Edge Function `const` fixes are not a deployed backend test.
- Real sign-in, email, backend writes, paid AI requests and production flows were not exercised. No backend/network credentials are required by these fixture-based checks.
- Remaining dependency vulnerabilities, legacy hook warnings, bundle-size warnings and unresolved font references remain visible work, not passing acceptance claims.
- No autonomous repair service, production deploy or auto-merge was enabled.
